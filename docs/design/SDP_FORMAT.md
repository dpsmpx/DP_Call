# Формат SDP-строки DP_Call

**Версия:** 1

```
DPCALL1.<type>.<payload>
```

- `O` = Offer
- `A` = Answer
- payload = base64url(gzip(json(SdpPayload)))

SdpPayload:

| Поле | Назначение |
|---|---|
| `sdp` | SDP-описание сессии |
| `candidates` | ICE-кандидаты в виде `mid\|mLineIndex\|candidate` |
| `identity` | код отправителя (публичный ключ), необязательное |
| `ts` | время создания, мс |
| `callId` | идентификатор звонка: связывает приглашение и ответ, необязательное |
| `sig` | подпись Шнорра (BIP-340, hex) ключом `identity` над типом и всеми остальными полями |

При ручной передаче подпись обязательна: строка без подписи или с подписью другого ключа
отклоняется. Ограничения: строка — до 64 КБ, распакованные данные — до 256 КБ,
кандидатов — до 64.

Строка передаётся двумя путями: внутри зашифрованного сообщения сигнального канала
(см. [ADR-002](../adr/002-relay-signaling.md)) либо вручную через мессенджер.
`SignalCodec.extract` находит строку в произвольном тексте сообщения.

Модуль: `com.dpsmpx.dpcall.signaling`

## DPCALL2 (с 1.3.1)

`DPCALL2.<O|A>.<base64url>` содержит DEFLATE без zlib-заголовка со словарём,
закреплённым в `CompactSignal.kt`. Изменять этот словарь без новой версии нельзя.
Распакованные поля (big-endian): timestamp int64; SDP; число кандидатов int32 и
кандидаты; identity; callId; флаг наличия подписи byte; подпись 64 байта. Строки —
длина UTF-8 int32 и байты; `-1` означает null. Подпись проверяется по тому же
каноническому представлению исходных полей, что и DPCALL1. Ограничения размеров
сохраняются; хвостовые и оборванные данные отклоняются.

SDP и неизвестные атрибуты сохраняются полностью. Формат применяется для SMS и
для ответов по релеям после получения аутентифицированного `signalVersion: 2`.
Первое приглашение совместимо с DPCALL1. После получения `ringing` повторы
приглашения уже останавливаются, поэтому дополнительная ссылка-повтор не нужна.
При отсутствии подтверждения полное приглашение повторяется: ссылка не поможет
телефону, который ещё не получил исходный эфемерный сигнал.

SMS передаёт читаемые подписанные данные подключения, включая адреса маршрутов;
это не шифрование содержимого SMS. Обоим телефонам нужна версия 1.3.1 или новее.
