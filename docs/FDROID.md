# Публикация в F-Droid

> **Публикация отменена.** Приложение распространяется только через GitHub Releases и само
> сообщает о новых версиях. Этот документ и каталог `docs/fdroid/` сохранены как архив и
> описывают состояние на версию 1.1.1.

F-Droid сам собирает приложение из исходников. «Аккаунта разработчика», как в Google Play,
у F-Droid нет: ничего не нужно оплачивать и подтверждать. Приложение добавляют заявкой
(merge request) в репозиторий [fdroiddata](https://gitlab.com/fdroid/fdroiddata) на GitLab —
для этого нужен только обычный бесплатный аккаунт GitLab.

## Что уже готово

| Скриншоты, по 4 на язык, 1080×2400 | `…/images/phoneScreenshots/1.png … 4.png` |
| Список изменений версии | `…/changelogs/5.txt` |
| Лицензия MIT, тег `v1.1.1`, подписанный APK в GitHub Releases | репозиторий |

Скриншоты: 1 — контакты, 2 — входящий звонок, 3 — разговор, 4 — журнал звонков. Это
настоящие экраны приложения с демонстрационными данными; они снимаются командой
`./gradlew testDebugUnitTest -Pscreenshots` (эмулятор не нужен) и перезаписывают файлы
в `fastlane/`. Если интерфейс изменился — запустите команду снова.

## Перед подачей

1. **Версия в файле метаданных.** Файл подготовлен для версии 1.1.1 (коммит тега
   `v1.1.1` уже вписан). Если к моменту подачи вышла более новая версия, замените
   `versionName`, `versionCode`, `commit` (полный хеш коммита тега), `CurrentVersion`
   и `CurrentVersionCode`.
2. **Сверьте отпечаток ключа.** В файле метаданных указан SHA-256 сертификата, которым
   подписаны релизы:
   `f936930cdb8818d4ddd243f0d5d3a8fc046f284402406584545b490d15b1cddb`.
   Проверьте: `keytool -list -v -keystore <ваш файл> | grep SHA256` (то же значение,
   с двоеточиями и в верхнем регистре).

## Риски: о чём знать заранее

- **Возраст проекта.** Правила F-Droid (Inclusion Policy, Quality Control, п. 6) требуют,
  чтобы приложение активно разрабатывалось не менее трёх месяцев. Исключения: у приложения
  уже есть пользователи; у автора есть другие приложения в F-Droid. История репозитория
  начинается 11 ноября 2026 года, так что заявку могут отложить до февраля 2027-го. Если
  у вас есть чем подтвердить исключение — напишите об этом в заявке.
- **Идентификатор `com.dpsmpx.dpcall`.** F-Droid советует идентификатор от собственного
  домена и отклоняет приложения, чей идентификатор совпадает с чужим доменом. Если домен
  `dpsmpx.com` принадлежит не вам, ревьюеры могут попросить заменить идентификатор на
  `io.github.dpsmpx.dpcall` — это снова будет новое приложение для уже установивших.

## Шаги

Всё можно сделать в браузере, в том числе с телефона: Git и Docker не нужны.

### 1. Аккаунт GitLab

1. Откройте <https://gitlab.com/users/sign_up>, укажите имя, почту и пароль (или войдите
   через GitHub) и подтвердите почту.
2. GitLab может попросить подтвердить номер телефона или карту. Для заявки в F-Droid
   карта не нужна: если её требуют для запуска проверок (CI), ничего не вводите, а
   напишите об этом в заявке — проверку запустят сами сопровождающие F-Droid.

### 2. Форк fdroiddata

1. Откройте <https://gitlab.com/fdroid/fdroiddata> и нажмите **Fork**.
2. Namespace — ваш логин, Visibility level — **Public**. Нажмите **Fork project**.

### 3. Ветка и файл метаданных

1. В своём форке: **Code → Branches → New branch**, имя `com.dpsmpx.dpcall`, от `master`.
2. Переключитесь на эту ветку, откройте папку `metadata`, нажмите **+ → New file**.
3. Имя файла: `com.dpsmpx.dpcall.yml`. Вставьте содержимое
   [`docs/fdroid/com.dpsmpx.dpcall.yml`](fdroid/com.dpsmpx.dpcall.yml) без изменений.
4. Commit message: `New app: DP Call`. Нажмите **Commit changes**.

Больше ничего в форк добавлять не нужно: описание и картинки F-Droid берёт из
репозитория приложения.

### 4. Проверка

Откройте **Build → Pipelines** в форке и дождитесь результата (10–40 минут). Зелёный
значок — можно подавать. Красный — откройте упавшее задание, там будет причина; если
она непонятна, подавайте заявку и спросите ревьюеров.

### 5. Заявка

1. **Merge requests → New merge request**: source — ваш форк, ветка `com.dpsmpx.dpcall`;
   target — `fdroid/fdroiddata`, ветка `master`.
2. Заголовок: `New app: DP Call`.
3. Описание: GitLab подставит шаблон; заполните его по
   [`docs/fdroid/MERGE_REQUEST.md`](fdroid/MERGE_REQUEST.md).
4. Нажмите **Create merge request**.

### 6. Ревью

Ревьюеры — волонтёры; первый ответ обычно приходит за несколько дней, включение занимает
от недели до месяца. Отвечайте на вопросы в заявке (уведомления приходят на почту). Если
просят изменить файл — правьте его в той же ветке форка, новая заявка не нужна. После
слияния приложение появляется в каталоге в течение нескольких суток.

### Локальная проверка (по желанию)

Нужен компьютер с Docker:

```bash
git clone https://gitlab.com/<ваш-логин>/fdroiddata.git && cd fdroiddata
docker run --rm -it -v "$PWD":/repo registry.gitlab.com/fdroid/fdroidserver:buildserver bash
# внутри контейнера:
cd /repo
fdroid readmeta
fdroid rewritemeta com.dpsmpx.dpcall
fdroid lint com.dpsmpx.dpcall
fdroid build -v -l com.dpsmpx.dpcall
```

## О чём, скорее всего, спросят

Лучше сразу написать об этом в описании merge request.

- **Сеть.** Приложение подключается к публичным релеям Nostr (сигналинг), STUN-серверам
  Google и Cloudflare и публичному TURN `staticauth.openrelay.metered.ca`. Всё это открытые протоколы, свои
  серверы не используются. Ревьюеры могут поставить отметку (anti-feature) **NonFreeNet**
  из-за STUN/TURN — это не препятствие для включения.
- **Готовые бинарные библиотеки.** WebRTC (`io.getstream:stream-webrtc-android`, BSD/Apache-2.0)
  и secp256k1 (`fr.acinq.secp256k1`, Apache-2.0) подключаются с Maven Central и содержат
  нативный код. Обе библиотеки открытые; если ревьюеры попросят собирать их из исходников,
  это отдельная задача — сообщите, поможем с рецептом сборки.
- **Камера.** Используется только для сканирования QR-кода контакта (библиотека ZXing,
  Apache-2.0); разрешение запрашивается в момент сканирования.
- **Постоянное уведомление и работа в фоне.** Нужны, чтобы принимать звонки без push-сервисов
  Google; отключаются в настройках.
- **Ключ подписи в репозитории** (`app/debug.keystore`). Публичный тестовый ключ, только
  для промежуточных сборок GitHub; выпуски подписаны закрытым ключом, которого в
  репозитории нет.

## Воспроизводимая сборка и подпись

В метаданных указаны `Binaries` и `AllowedAPKSigningKeys`: F-Droid собирает приложение
сам, сверяет результат с APK из GitHub Releases и, если они совпали, распространяет APK
с **вашей** подписью. Тогда сборки из F-Droid и из GitHub взаимозаменяемы и обновляют
друг друга. F-Droid просит включать это сразу: позже перейти со своей подписи F-Droid на
вашу нельзя.

Проверено на 1.1.0: чистая сборка тега другим JDK (21 вместо 17) совпала с опубликованным
APK во всём, кроме служебного файла `META-INF/version-control-info.textproto`. С версии
1.1.1 этот файл в APK не включается (`vcsInfo.include = false`).

Если сверка у F-Droid всё же не пройдёт и причину не удастся устранить, уберите из файла
строки `Binaries` и `AllowedAPKSigningKeys` — приложение подпишут ключом F-Droid. В этом
случае сборки из двух источников не обновляют друг друга, как и написано сейчас в README.

## Обновления

В метаданных указано `AutoUpdateMode: Version` и `UpdateCheckMode: Tags`: F-Droid сам
находит новые теги вида `v1.2.3`, берёт `versionCode`/`versionName` из
`app/build.gradle.kts` и собирает новую версию. От вас — только выпуск по
[RELEASING.md](RELEASING.md) с файлом `changelogs/<versionCode>.txt`.

## После публикации

Страница приложения будет по адресу <https://f-droid.org/packages/com.dpsmpx.dpcall/>
(адрес определяется идентификатором пакета, поэтому известен заранее).

В `README.md` для этого уже есть место: в разделе «Установка» уберите пометку
«*ожидает публикации*» у ссылки на F-Droid. Сам адрес записан в последней строке файла
(`[fdroid]: …`) — менять его нужно, только если он окажется другим.

## Важно для пользователей

Пока приложение не опубликовано, в `README.md` и `USER_GUIDE.md` сказано, что сборки из
F-Droid и из GitHub подписаны разными ключами. Если F-Droid примет воспроизводимую сборку,
это перестанет быть верным — поправьте оба места после публикации.

## Альтернатива: запрос без merge request

Можно создать заявку в <https://gitlab.com/fdroid/rfp/-/issues> (Request For Packaging) и
приложить ссылку на репозиторий — метаданные напишут волонтёры, но это заметно дольше.


## Нативные модули с версии 1.4.0

Обычный APK теперь также включает транспорт комнат на Go. Перед Gradle нужен
`carrier/mobile.aar`, собранный из закреплённых исходников; команды и лицензии
описаны в [carrier/UPSTREAM.md](../carrier/UPSTREAM.md). `carrier/build.sh` требует
Go 1.26.1 и NDK 29.0.14206865 и собирает оба варианта для GitHub Actions.
Шаблон metadata в docs/fdroid описывает прежний выпуск 1.1.1; его нельзя считать
готовым рецептом сборки 1.4.0 для инфраструктуры F-Droid без добавления этапа Go/NDK.
Никаких заявок или обновлений в F-Droid в рамках этого выпуска не отправлялось.
