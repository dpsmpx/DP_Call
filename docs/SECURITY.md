# Безопасность DP Call

Сообщить об уязвимости: <https://github.com/dpsmpx/DP_Call/security/advisories/new>
(или issue без технических деталей с просьбой связаться).

## Что защищается и от кого

| От кого | Что он может | Что не может |
|---|---|---|
| Релей Nostr | видеть IP, обезличенный тег получателя, время и размер сообщений; хранить до 48 часов зашифрованную отметку о пропущенном звонке; не доставить или задержать сообщение | узнать коды, кто кому звонит, содержимое; подделать вызов от имени контакта |
| STUN/TURN-сервер | видеть IP обоих участников; TURN — объём зашифрованного трафика | расшифровать звук |
| Посторонний в сети | видеть факт соединения и объём трафика | прочитать сигналы и звук |
| Тот, кто знает ваш код | позвонить вам (как «Неизвестный абонент»), видеть, что вы на связи (ответ «звонит») | выдать себя за другого; узнать ваш IP, пока вы не приняли звонок |
| Другое приложение на телефоне | открыть DP Call, передать ему текст через «Поделиться», открыть окно «Новый контакт» с произвольным кодом | принять звонок или позвонить за вас; добавить контакт без вашего подтверждения; подставить поддельное приглашение или ответ; прочитать ключ и контакты |
| Релей Nostr, сборка с Tor | то же, но вместо вашего IP — адрес выхода Tor | связать сигналы с вашим IP |
| GitHub | видеть IP при ежедневной проверке версии (в сборке с Tor — адрес выхода Tor); не сообщить о новой версии | подсунуть чужое обновление: система ставит APK только с той же подписью, а ссылка принимается только на файлы выпусков этого репозитория |
| Тот, у кого файл резервной копии | перебирать пароль без ограничений | прочитать ключ и контакты без пароля |

## Как это обеспечено

- **Личность — ключ.** Код пользователя — публичный ключ secp256k1. Секретный ключ хранится
  зашифрованным ключом Android Keystore, резервные копии отключены.
- **Сигнальный канал.** Каждое сообщение — событие Nostr, подписанное одноразовым ключом
  и зашифрованное AES-256-GCM в два слоя (см. [ADR-002](adr/002-relay-signaling.md)).
  Внутренний слой может создать только владелец кода отправителя.
- **Ручная передача.** Строки DPCALL1 подписываются ключом отправителя (подпись Шнорра над
  всеми полями, включая отпечаток DTLS внутри SDP). Неподписанные и изменённые строки
  отклоняются; ответ принимается только от того, кому вы звоните.
- **Звук.** DTLS-SRTP напрямую между устройствами. Отпечаток ключа DTLS входит в
  подписанный/зашифрованный сигнал, поэтому подменить собеседника «посередине» нельзя,
  не владея его ключом.
- **Приём звонка.** Только из собственного уведомления приложения (одноразовый токен),
  с экрана или с гарнитуры. «Перезвонить» из уведомления о пропущенном — тоже только с
  секретным токеном приложения.
- **Отметки о пропущенных.** Тот же конверт, что и у сигналов: отправителя удостоверяет
  внутренний слой. Хранимым событием принимается только отметка, повторы отсекаются по
  идентификатору звонка, сохранённому на устройстве; на незнакомые коды действуют тот же
  предел частоты и режим «Только от контактов».
- **Обновления.** Приложение ничего не скачивает и не устанавливает: оно только сообщает
  о версии и открывает в браузере APK со страницы выпусков. Подлинность обновления
  проверяет Android — по подписи установленной версии.
- **Резервная копия.** Создаётся только по явному действию. Ключ шифрования выводится из
  пароля PBKDF2-HMAC-SHA256 (600 000 итераций), данные шифруются AES-256-GCM.
- **Входные данные.** Размер сигнала, распакованных данных и число ICE-кандидатов ограничены.
- **Незнакомые абоненты.** Не более трёх звонков за 10 минут; режим «Только от контактов»
  отбрасывает их совсем.
- **Журнал ошибок.** Хранится локально, отправляется только вручную; коды, ключи, SDP и
  IP-адреса в него не попадают.
- **Сборка.** Действия GitHub закреплены по хешу коммита, секреты подписи доступны только
  шагу сборки, выпуск без ключа подписи невозможен.

## Известные ограничения

- **Нет прямой секретности для сигналов.** Если секретный ключ устройства будет украден,
  ранее записанные сигнальные сообщения можно расшифровать (сам звук — нет: у него свои
  одноразовые ключи DTLS). Релеи эфемерные события не хранят, но гарантировать это нельзя.
- **Собеседник узнаёт ваш IP-адрес** — это свойство прямого соединения. Скрыть: VPN или
  свой TURN-сервер. Сборка с Tor этого не меняет: через Tor идёт только сигнальный канал.
- **Режим белых списков** мобильного интернета не обойти без сервера в разрешённой сети:
  звонок в нём не пройдёт. Приложение лишь честно об этом сообщает.
- **Встроенные мосты Tor общедоступны** — их легко заблокировать; свои мосты надёжнее.
- **Tor в сборке с Tor — сторонний код** (tor-android от Guardian Project, BSD-3):
  нативная libtor.so из опубликованного AAR. Пока цепочка Tor не построена, приложение к
  релеям не подключается, так что настоящий адрес релеям не уходит и при сбое Tor.
- **Метаданные.** Тот, кто знает ваш код, может подписаться на ваш «ящик» на релеях и
  видеть время и число адресованных вам сообщений (не содержимое). Отметки о пропущенных
  делают это возможным и задним числом — за последние 48 часов; отключаются в настройках.
- **Резервная копия защищена только паролем.** Слабый пароль можно подобрать, получив
  файл. Украденные файл и пароль равносильны украденному ключу; сменить код можно только
  переустановкой приложения.
- **Один код на двух телефонах** (после восстановления из копии) — звонки приходят на оба,
  кто ответит первым, тот и разговаривает.
- **Проверка версии раскрывает GitHub ваш IP-адрес** раз в сутки; отключается в настройках.
- **Повтор сообщения.** Перехваченное приглашение можно повторно отправить в течение
  5 минут (30 минут для ручной строки); приложение отсекает повторы по идентификатору
  звонка, но только пока оно не перезапускалось. Результат — ложный звонок от контакта,
  без возможности соединиться.
- **Украденный ключ получателя** позволяет выдавать себя перед ним за любого абонента
  (свойство аутентификации общим секретом).
- **Доступность.** Релеи и публичный TURN — чужие бесплатные сервисы без гарантий.
- **Экран блокировки.** Во время звонка экран звонка доступен без разблокировки, как в
  обычной звонилке (включая кнопку «Добавить в контакты»).
- **Тестовый ключ** `app/debug.keystore` публичен; им подписываются только отладочные и
  промежуточные сборки без секретов.
- Независимого внешнего аудита не было.

## Optional Telemost / VK rooms (1.4.0+)

Both standard and Tor APKs offer an optional, disabled-by-default third-party guest room
for signaling and encrypted voice packets. The service sees participants, IP
addresses, timing and traffic volume; DP Call retains end-to-end DTLS-SRTP and
adds pair-key authenticated encryption around the carrier packets. No automatic
public relay, STUN/TURN fallback or update check runs while this mode is selected, including after a room failure. Leaving restores
the previous regular signaling settings. Tor is paused during room mode;
connections to the room service are direct and expose the IP to that service. Room links
and guest authentication credentials are not written to the app log. Session
configuration is kept in memory. See [setup and limitations](ROOM_CALLS.md)
and [implementation/licensing](../carrier/UPSTREAM.md). SMS signal exchange is
signed, but SMS contents (including ICE addresses) are not encrypted.
